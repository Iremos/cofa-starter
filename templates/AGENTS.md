# 작업 규칙 (Codex는 이 파일을 항상 따른다)

## 진행 방식
- 구현 전에 계획(만들 것 / 만들지 않을 것 / 검증 방법)을 먼저 보여 주고 승인을 받는다.
- 요구 사항에 없는 기능, 라이브러리, 추상화는 추가하지 않는다. 애매하면 추측하지 말고 묻는다.
- 판정·계산·집계는 고정된 코드와 테스트로 처리한다. AI 판단은 해석·초안에만 쓴다.
- 지시받은 단계만 수행하고 멈춘다. 다음 단계로 임의로 넘어가지 않는다.

## 구조 (책임 분리)
- 입력 반영(업로드·검증·저장), 계산(도메인 로직), 게시(확정·버전), 조회(읽기 전용)를 별도 모듈로 나눈다.
- 계산 로직은 DB·HTTP를 모르는 순수 함수로 만들고 단독으로 테스트한다.
- 조회 경로는 계산을 직접 실행하지 않고, 확정된 결과만 읽는다.

## 검증
- 작업 단위가 끝날 때마다 실행 또는 테스트로 확인하고, 실제 출력 결과를 보고한다.
- "완료"라고 말하기 전에 검증 명령과 결과를 함께 제시한다.
- 검증 보고에는 **사용자가 자기 터미널에서 직접 돌릴 확인 명령 2~3개**를 기대값과 함께 따로 적는다.
  기대값은 구현 코드가 아니라 입력 데이터·규칙으로부터 계산한 근거를 붙인다.

## 운영 리스크
- 기능을 만들 때 다음을 점검하고, 작게 대비할 수 있으면 제안하고, 아니면 DECISIONS.md 리스크 표에 기록한다:
  동시 수정, 서버 장애 시 조회, 잘못된 입력, 개인정보·권한, 규칙 변경의 파급, 실행 불가능한 조건, 규모 증가, 변경 이력.
- 제안만 하고 승인 없이 구현하지 않는다.

## 기록
- 의미 있는 단위로 git commit 한다. 메시지는 한글로 "무엇을, 왜"를 쓴다.
- 결정과 근거는 DECISIONS.md에, 진행 상태는 HANDOFF.md에, 검증 기록은 VERIFY.md에 누적한다.
- 단계 종료: $handoff / AI 제안 수정·거절: $ai-decision-log / 단계 검증: $verify-manual / 제출 직전: $verify-before-submit
- DECISIONS.md는 해당 섹션의 표에 **행을 추가**한다. 기존 행을 지우지 않는다 (바뀐 결정은 새 행 + "○○ 대체").
- 사용자가 담당자와 합의했다고 전달한 내용만 "합의"로 기록한다. 담당자 대화는 볼 수 없으므로 추측해서 적지 않는다.
- 지시에 `[기록]` 줄이 있으면 그 내용을 지정된 문서·섹션에 반영한다.
- **매 답변 끝에 한 줄로 문서 갱신을 보고한다.** 예: `문서 갱신: DECISIONS 3번 +1행, VERIFY +2행 (커밋 a1b2c3)`
  바뀐 문서가 없으면 `문서 갱신 없음`. 이번 답변에서 기록할 만한 결정이 있었는데 반영하지 않았다면 `기록 제안: …`으로 알린다.

## 참고 문서 (웹 과제)
- 화면을 만들 때는 `docs/DESIGN.md`(색·서체·컴포넌트·화면 상태 5종)를 따른다.
- 웹 앱 구조는 `docs/ARCHITECTURE.md`(FSD-lite 계층, server/ 분리, 관리자/사용자 분리, 동시성 제어, 스냅샷·캐시)를 따른다.
  필수(●)만 만들고, 선택(○)은 필요한 이유를 말하고 승인을 받은 뒤 만든다.
- 두 문서와 다르게 해야 하면 이유를 먼저 말하고 승인을 받은 뒤, DECISIONS.md 3번에 기록한다.
- 담당자가 말한 사용 환경·요구 사항이 두 문서의 기본값보다 우선한다.

## 보안
- 비밀번호, 키, 개인정보, 사외비(단가, 레시피, 주소 등)는 코드, 로그, 화면, API 응답에 넣지 않는다.
- 민감 정보는 화면에서 숨기는 것이 아니라 서버 응답 단계에서 제거한다.

## 외부 전송
- 문제, 제공 파일, 결과물을 외부로 보내지 않는다.
- Context7 등 외부 문서 검색에는 **라이브러리 이름·버전과 주제만** 보낸다 (예: "next.js route handlers", "better-sqlite3 transaction").
  과제 문장, 데이터, 코드, 파일 내용을 검색어에 넣지 않는다.
- 도구의 사용 통계 전송은 끈다: Next.js는 `NEXT_TELEMETRY_DISABLED=1`, Chrome DevTools MCP는 `--no-usage-statistics --no-performance-crux`.
- 새 MCP·스킬·패키지가 외부로 데이터를 보내는지 모르면 추가하기 전에 묻는다.

## 환경
- 웹 서버는 0.0.0.0에 바인딩한다. 외부 CDN을 쓰지 않는다 (서체도 self-host 또는 시스템 서체, DESIGN.md 참고).
- 계속 실행되는 서버는 직접 띄우지 말고 실행 명령만 알려 준다 (사용자가 별도 터미널에서 실행).
- 답변은 한국어로 한다.
