# cofa-starter

Codex CLI로 업무형 과제를 풀 때 쓰는 개인 시작 세팅과 행동 방침입니다.
작업 규칙(AGENTS.md), 프로젝트 스킬 3개, 문서 템플릿 2개로 구성됩니다. 과제 답안이나 코드는 포함하지 않습니다.

> 막히면 이 문서로 돌아온다. **"무엇을, 어떤 제약으로, 어디까지, 어떻게 확인할지"는 매번 내가 정한다.**

---

## 0. 시작 (2분)

```bash
git clone https://github.com/<계정>/cofa-starter /tmp/starter
bash /tmp/starter/bootstrap.sh          # context7까지: WITH_CONTEXT7=1 bash /tmp/starter/bootstrap.sh
codex                                    # → /status 로 모델·권한 확인
```

이 문서는 다른 터미널 탭에서 `less /tmp/starter/README.md` 로 열어 둔다.

| 파일 | 언제 | 어떻게 |
|---|---|---|
| `AGENTS.md` | 항상 (자동) | Codex가 자동으로 읽음. 과제에 맞는 규칙은 "AGENTS.md에 ○○ 추가해" |
| `DECISIONS.md` | 합의 후, 검증 후 | "합의 내용으로 DECISIONS.md 1~4번 채우고 커밋해" |
| `$handoff` | 단계 끝날 때 | HANDOFF.md 갱신 + 커밋 → 필요하면 `/new` |
| `$ai-decision-log` | AI 제안을 바꾸거나 거절할 때 | `$ai-decision-log 캐시 제안 거절. 하루 1회 갱신이라 불필요` |
| `$verify-before-submit` | 제출 15~20분 전 | 실행·요구 사항·보안·문서 대조·리스크 점검 |

스킬이 안 먹히면 같은 내용을 말로 시키면 된다.

## 1. 전체 흐름 (180분)

| 시간 | 단계 | 끝났다는 증거 |
|---|---|---|
| 0~10 | 세팅 | 첫 커밋 |
| 10~40 | **조사 + 담당자 대화 + 서면 합의** | DECISIONS.md 1~4번, `$handoff`, `/new` |
| 40~140 | **단계별 구현 + 검증** | 단계마다 테스트 결과 + 커밋 |
| 핵심 완성 시 | 인계 | `$handoff`, `/new` |
| 140~165 | 검증 + 문서 | `$verify-before-submit`, DECISIONS.md 5~7번 |
| 165~180 | 제출 | 종료 10분 전 제출 시작, 코드·DECISIONS.md 다시 읽기 |

**Codex가 일하는 동안 기다리지 않는다.** 그 시간에 담당자 대화, 문서, 결과 검산.
**승인 대기로 멈춰 있지 않은지** 수시로 확인한다.

## 2. 담당자 대화 (소통)

**처음 3분은 해결책 단어("자동화", "AI") 없이**
1. 에피소드: "최근에 이 일 때문에 곤란했던 일 하나만 얘기해 주실 수 있어요?"
2. 임시방편: "지금은 어떻게 하고 계세요?"
3. 정량화: "일주일에 몇 번, 몇 분씩 걸려요?"
4. 당사자: "결과물은 누가, 언제, 어디서 쓰나요?"
5. 경계: "이번에 꼭 할 것과 안 해도 되는 건요?"

**데이터 의문은 근거를 들고**
- ○ "수량이 빈칸이거나 -2인 행이 있던데, 어떻게 보여 드릴까요?"
- × "데이터에 특이한 점 있나요?"

**합의는 글로 정리해 확인받기**
```
정리하면 - 문제: / 만들 것: / 안 만들 것: / 성공 기준: / 제약:
이렇게 진행해도 될까요?
```

담당자 말은 **요약해서** Codex에 넘긴다. 대화 통째 붙여넣기 금지.

## 3. Codex 지시 방식 (의도: 변별력 최대)

### 모든 위임에 4요소

```
[목표]     무엇을 만든다
[제약]     하지 말 것, 지켜야 할 규칙, 건드리지 말 범위
[완료 기준] 어떤 결과가 나오면 끝인가 (숫자·케이스로)
[검증]     무엇을 실행해서 보여 줄 것인가 → 그다음 커밋
```

예:
```
[목표] 재고 합산과 상태 판정 함수를 만들어.
[제약] 빈칸·음수는 0으로 처리하지 말고 "확인 필요". 단가 컬럼은 다루지 마. 새 라이브러리 금지.
[완료 기준] 빈칸, 음수, 안전재고와 같은 값, ALL 유형 테스트 통과.
[검증] 테스트 결과와 대표 2건의 판정 결과를 출력하고 커밋.
```

### 단계별 지시 템플릿

**① 조사 (아무것도 만들지 않기)**
```
README와 제공 파일을 모두 읽고 조사해. 아직 어떤 파일도 만들거나 고치지 마.
- 파일별 형식, 컬럼 의미, 행 수, 인코딩
- 빈칸, 음수, 중복, 표기 불일치 같은 이상 데이터
- 민감해 보이는 정보 (개인정보, 단가, 사외비)
- README에 언급되지 않은 파일이나 폴더
```

**② 계획 (코드 금지)**
```
합의 내용: (요약)
DECISIONS.md 1~4번을 채우고 커밋해. 그다음 구현 계획을 단계별로 보여 줘.
각 단계마다 완료 기준과 검증 방법을 붙여. 아직 코드는 쓰지 마.
```

**③ 계획 쳐 내기**
```
○번, ○번은 빼. (이유: 담당자가 불필요하다고 함)
1단계만 하고 멈춰. 결과 보여 주고 커밋.
```

**④ 결과 확인 (완료 선언을 믿지 않기)**
```
"완료"라고 하지 말고 실행 결과를 보여 줘.
테스트에 ○○ 케이스가 없어. 추가해서 다시 돌려.
```

**⑤ 판단과 계산 분리**
```
판정·계산은 고정 코드와 테스트로 해. AI가 판단하게 하지 마.
○○은 초안만 뽑아 줘. 내가 검토해서 확정할게.
```

**⑥ 맥락 갱신**
```
담당자 확인 결과 ○○가 바뀌었어. DECISIONS.md에 반영하고 남은 계획을 갱신해.
```

**⑦ 세션 전환**
```
$handoff
/new
AGENTS.md와 HANDOFF.md 읽고 '다음 세션의 첫 행동'부터 이어가.
```

### 점수 차를 만드는 장면 3가지 (기록에 꼭 남기기)

1. **AI 제안을 이유와 함께 거절** → `$ai-decision-log`
2. **AI 오류를 직접 잡아냄** ("테스트는 통과했는데 ○○ 케이스가 없어")
3. **판단과 계산의 경계를 내가 정함** (판정은 코드, AI는 초안)

### 세부 항목 체크

- [ ] 문제·제약 정의: 구현 전 조사, 제약 명시
- [ ] Output 목표 구체화: 완료 기준을 숫자·케이스로
- [ ] 작업 분해·위임: 계획을 받고 내가 잘라내고 순서 결정
- [ ] 검증 루프: 단계마다 실행 결과 요구, 틀린 것 지적
- [ ] 의도 갱신·맥락 유지: 담당자 변경 사항 즉시 반영, handoff
- [ ] 재사용 체계: AGENTS.md, 스킬, 템플릿

## 4. 하지 말 것

- 지시서 통째로 붙여넣고 "해 줘"
- "다시 해 줘" 반복 (무엇이 틀렸는지 짚어서 지시)
- 요구에 없는 기능 (로그인, 대시보드, DB, 실시간 연동, 알림…)
- 문서에만 있는 검증 주장 (근거 커밋·테스트가 있어야 함)
- 보여 주기용 단계 추가
- 키, 개인정보, 사외비를 코드·로그·화면·API 응답에 넣기
- Codex 버전 업데이트

## 6. 서술형 (6문항 × 5분, AI 없이 직접 타이핑)

**3단계로 쓴다**
1. **약점 지점**: 파일·함수·규칙을 구체적으로 지목
2. **파급**: 왜, 누구에게, 어떻게 위험한가
3. **다음 계획**: 무엇을 검증·개선할 것인가

"왜 이렇게 만들었나" → 결정 → 근거 → 한계와 대안

**전제가 틀린 질문은 바로잡는다**: "○○는 구현하지 않았습니다. 이유는 ~, 대신 ~"

250~400자, 구체적인 함수명과 숫자. 제출 전 DECISIONS.md의 "AI 판단 기록"과 "리스크 표"를 다시 읽는다.

## 7. 막혔을 때

| 상황 | 대응 |
|---|---|
| Codex가 엉뚱한 방향 | Esc로 중단 → "그게 아니라 ~" |
| 대화가 길어져 맥락이 흐려짐 | `$handoff` → `/new` |
| 스킬 인식 안 됨 | 같은 내용을 말로 지시 |
| 담당자가 모호하게 답함 | 더 구체적으로, 근거를 들고 다시 질문 |
| 시간이 부족 | 기능 추가 중단 → 검증과 DECISIONS.md 우선 |
| 플랫폼 오류 반복 | 상단 "문제 신고" (시각, 직전 동작, 오류 문구) |

## 구성

| 파일 | 역할 |
|---|---|
| `templates/AGENTS.md` | 계획 먼저, 범위 밖 기능 금지, 단계별 검증·커밋, 보안, 0.0.0.0 바인딩 |
| `templates/HANDOFF.md` | 세션 전환용 인계 문서 양식 |
| `templates/DECISIONS.md` | 문제 정의, 결정과 근거, 검증 결과, 리스크 표 양식 |
| `.agents/skills/handoff` | HANDOFF.md 갱신 후 커밋 |
| `.agents/skills/ai-decision-log` | AI 제안의 수용·수정·거절 기록 |
| `.agents/skills/verify-before-submit` | 제출 직전 점검 |
| `bootstrap.sh` | 위 파일을 작업 폴더에 복사, git 초기화·커밋 (기존 파일은 덮어쓰지 않음) |
